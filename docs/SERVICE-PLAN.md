## 0. 현재 상태 (As-Is) 요약

| 항목 | 현재 (v1) | 목표 (v2) |
|---|---|---|
| 시세 산출 | 정률법 감가 공식 (`app.js`의 `calculatePrice`) — 추정치 | 네이버 쇼핑 API 실데이터 누적 → 3개월 시세 그래프 |
| 데이터 | `products.json` 59개 모델 시드 (출시가 기준) | 모델별 일별 평균가 시계열 DB |
| 페이지 | `build.js`로 생성한 정적 랜딩 59개 (`/price/*.html`) | 동일 구조 유지 + 그래프·최고/최저가·아웃링크 블록 삽입 |
| 호스팅 | GitHub Pages (정적) | 정적 프론트 유지 + 데이터 수집 워커(서버리스/GitHub Actions) 분리 |
| 수익화 | 애드센스 신청 단계 | 3단계 수익화 (광고 → 리드 → B2B) |

**핵심 설계 원칙**: 프론트는 지금처럼 정적으로 유지한다. 데이터 수집만 백엔드 워커가 담당하고, 결과물은 정적 JSON으로 커밋/배포한다. → 서버 비용 0원, 법적 리스크 0, 기존 SEO 자산(색인된 59개 페이지) 그대로 계승.

## 1. 서비스 정의 및 타겟 페인 포인트

### 1.1 한 줄 정의

> **"내 가전, 지금 팔면 얼마?"** — 가전·디지털 기기의 최근 3개월 중고 시세 그래프와 최고/최저가를 무료로 보여주고, 실제 매물은 당근마켓·중고나라로 안전하게 연결해 주는 시세 정보 서비스.

### 1.2 타겟 페르소나 & 페인 포인트

| 페르소나 | 상황 | 페인 포인트 | 우리의 해결 |
|---|---|---|---|
| **파는 사람** (이사·혼수 교체 30~40대) | 세탁기·냉장고를 내놓으려는데 얼마에 올릴지 모름 | 당근에서 남의 호가만 뒤지다 시세보다 싸게 팔거나, 비싸게 올려 안 팔림 | 3개월 평균가 + 최고/최저 밴드 → "적정 등록가" 즉시 제시 |
| **사는 사람** (가성비 추구 20~30대) | 중고 노트북·폰을 사려는데 지금이 살 타이밍인지 모름 | 시세 하락 중인지 상승 중인지 알 수 없음 | 3개월 추세선 → "지금 사도 되는 가격인지" 판단 근거 제공 |
| **정보 탐색자** (검색 유입) | "갤럭시 S24 중고가" 등 검색 | 검색 결과가 매물 리스트뿐, 요약된 '시세'가 없음 | 검색어당 1페이지로 시세 요약 (SEO 핵심 유입원) |

### 1.3 경쟁 우위 (Why us)

1. **무료 + 회원가입 불필요** — 조회 자체에 아무 장벽 없음 (트래픽 극대화 전략).
2. **플랫폼 중립** — 당근·중고나라 어느 쪽에도 종속되지 않은 제3자 시세 기준점.
3. **법적 클린** — 타 플랫폼 크롤링 없이 공식 API·공개 데이터만 사용. 제휴 분쟁 리스크 0.

## 2. 핵심 기능 정의 (Feature List)

### 2.1 메인 시세 검색 및 결과 화면

#### F-01. 시세 검색 (메인 페이지 상단)

- 입력: 제품명 자동완성 검색바. 데이터 소스는 `products.json`의 모델 목록(클라이언트 사이드 필터링, 서버 불필요).
- 자동완성 매칭: 초성 검색 지원 권장 (예: "ㄱㄹㅅ" → 갤럭시 S24). 모델 미등록 검색어는 "모델 요청하기" CTA로 수집(→ 4.2 리드 수집과 연결).
- 선택 시 해당 모델 페이지 `/price/{slug}.html`로 이동.

#### F-02. 시세 결과 화면 (모델별 페이지 — 기존 `/price/*.html` 확장)

페이지 위→아래 구성 (모바일 기준 1열):

1. **헤더 블록**: 제품명 + 카테고리 뱃지 + 출시년도/출시가
2. **시세 요약 카드** (핵심, First View 안에 배치)
   - `이번 주 평균 시세: 847,000원`
   - `3개월 최고가: 920,000원` / `3개월 최저가: 780,000원`
   - 전주 대비 등락: `▼ 2.3% (지난주보다 20,000원 하락)` — 색상: 하락 파랑, 상승 빨강 (국내 관례)
3. **3개월 시세 그래프** (F-03)
4. **상태별 예상가 테이블** (기존 v1 감가 로직 재활용): S급/A급/B급 × API 평균가 보정. v1의 `GRADE` 가중치(S 1.10 / A 1.00 / B 0.85)를 API 평균가에 적용하는 방식으로 전환.
5. **플랫폼 아웃링크 블록** (F-04)
6. **관련 꿀팁 링크** (기존 `/tips/` 콘텐츠 내부링크 — 체류시간·SEO)
7. **면책 고지 푸터** (6장)

#### F-03. 3개월 시세 그래프

- 라이브러리: **Chart.js 4.x** (번들 ~70KB, CDN 셀프호스팅 권장) — ApexCharts 대비 가볍고 현재 바닐라 JS 스택과 궁합이 좋음.
- 차트 타입: Line (주 단위 평균 12포인트) + 최고/최저 밴드(Area fill, 투명도 0.1).
- 데이터 소스: `/data/{slug}.json` (정적 파일, 3.3 참조). fetch 실패 시 그래프 영역을 숨기고 v1 감가 계산 결과로 폴백 — **그래프가 안 떠도 페이지는 항상 유효해야 함**.
- 데이터 포인트 12개 미만(신규 등록 모델)이면: "시세 데이터 수집 중입니다 (매주 업데이트)" 배너 + 있는 만큼만 표시.
- 접근성: `<canvas>`에 `aria-label="아이폰 16 최근 3개월 중고 시세 그래프, 최고 92만원 최저 78만원"` 형태의 요약 제공.

#### F-04. 중고 플랫폼 아웃링크 연동 규격

**딥링크 URL 조합 규칙** (크롤링·API 없이 검색 결과 페이지로만 연결):

| 플랫폼 | URL 패턴 | 예시 (갤럭시 S24) |
|---|---|---|
| 당근마켓 | `https://www.daangn.com/kr/buy-sell/?search={query}` | `.../buy-sell/?search=%EA%B0%A4%EB%9F%AD%EC%8B%9C%20S24` |
| 중고나라 | `https://web.joongna.com/search/{query}` | `https://web.joongna.com/search/%EA%B0%A4%EB%9F%AD%EC%8B%9C%20S24` |
| 번개장터 | `https://m.bunjang.co.kr/search/products?q={query}` | `.../search/products?q=%EA%B0%A4%EB%9F%AD%EC%8B%9C%20S24` |

- `{query}`는 반드시 `encodeURIComponent(제품명)` 처리. 검색어는 `products.json`에 `searchQuery` 필드를 신설해 모델별로 관리 (표시명과 검색 최적 키워드가 다를 수 있음 — 예: 표시명 "LG 트롬 세탁기 21kg" → 검색어 "LG 트롬 21kg").
- **구현 규칙 (법적/UX 가이드라인 준수)**:
  - `<a target="_blank" rel="noopener noreferrer nofollow">` 필수. **iframe 임베드 절대 금지.**
  - 타사 로고 이미지 사용 금지. 텍스트 버튼만 사용: `당근마켓에서 매물 보기 ↗` / `중고나라에서 매물 보기 ↗`
  - 버튼 하단 캡션: "외부 사이트로 이동합니다" (10~12px, 보조 텍스트 컬러)
  - URL 패턴은 타 플랫폼 개편 시 깨질 수 있으므로 `app.js`가 아닌 **설정 객체 한 곳**(`platforms.js` 또는 `products.json` 내 `_platforms` 키)에서만 관리. 분기별 1회 수동 링크 점검을 운영 체크리스트에 포함.
  - 클릭 이벤트는 GA4로 추적: `gtag('event', 'outlink_click', { platform, slug })` — 3단계 B2B 수익화의 근거 데이터가 됨.

## 3. 시스템 아키텍처 및 데이터 파이프라인

### 3.1 전체 구조 (비용 0원 원칙)

```
[수집 워커: GitHub Actions cron (1일 1회)]
        │  네이버 쇼핑 상품검색 API 호출 (모델당 1~2쿼리 × 59모델 ≈ 120쿼리/일 ≪ 25,000 한도)
        ▼
[가공: collect.js]  이상치 제거 → 일별 평균가 산출 → 숫자만 저장
        │
        ▼
[저장: /data/*.json + /data/history.csv]  ← 리포에 자동 커밋 (이게 곧 DB)
        │
        ▼
[배포: GitHub Pages 자동 재배포]
        │
        ▼
[프론트: /price/{slug}.html]  fetch('/data/{slug}.json') → Chart.js 렌더
```

- **DB 서버를 두지 않는다.** 일 1회 배치 수집이므로 리포지토리 내 JSON/CSV가 시계열 DB 역할을 충분히 한다. (59모델 × 365일 × ~50byte ≈ 연 1MB 수준)
- 나중에 모델이 500개+로 늘거나 실시간성이 필요해지면 그때 Supabase(무료 티어 Postgres)로 이관 — 스키마는 3.3과 동일하게 설계해 두었으므로 이관 비용 최소.

### 3.2 네이버 쇼핑 API 연동 명세

- 엔드포인트: `GET https://openapi.naver.com/v1/search/shop.json`
- 인증 헤더: `X-Naver-Client-Id`, `X-Naver-Client-Secret` → **GitHub Actions Secrets에 저장** (`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`). 코드·리포에 절대 노출 금지.
- 요청 예시: `?query=갤럭시 S24 중고&display=100&sort=asc`
- 가공 규칙 (collect.js):
  1. 응답 items 중 `title`에 모델 키워드 매칭 실패 항목 제외 (액세서리·케이스 오염 제거).
  2. `lprice` 기준 **IQR 방식 이상치 제거** (Q1−1.5×IQR 미만, Q3+1.5×IQR 초과 컷) — 1,000원짜리 부품·허위 매물 방어.
  3. 잔여 샘플 n≥5일 때만 유효 데이터로 인정. `avg`, `min`, `max`, `sampleCount` 산출.
  4. **저장은 숫자·날짜·모델 slug만.** 상품명 원문, 판매처명, 링크, 이미지 등 API 원본 콘텐츠는 저장하지 않는다(저작권·약관 리스크 차단 — 우리는 "통계"만 만든다).

### 3.3 데이터 스키마

**누적 원장 — `/data/history.csv`** (append-only, 수집 워커만 쓰기):

```csv
date,slug,avg,min,max,sample_count,source
2026-07-14,galaxy-s24,612000,548000,701000,37,naver
```

**프론트 서빙용 — `/data/{slug}.json`** (워커가 history에서 최근 90일을 주 단위로 리샘플링해 생성):

```json
{
  "slug": "galaxy-s24",
  "updatedAt": "2026-07-14",
  "period": { "high": 701000, "low": 548000, "avgThisWeek": 612000, "wowChangePct": -2.3 },
  "weekly": [
    { "week": "2026-04-14", "avg": 655000, "min": 590000, "max": 720000 }
  ]
}
```

`source` 컬럼이 핵심 — 데이터 출처를 행 단위로 기록해 두면 API 전환 후에도 과거 데이터와 신규 데이터를 한 원장에서 섞어 쓸 수 있다.

### 3.4 2026년 7월 31일 API 종료 대비 — 플러그인(어댑터) 구조

**⚠️ D-17. 이번 스프린트의 최우선 과제는 "종료 전 데이터 최대 적재"와 "어댑터 구조 선반영" 두 가지다.**

수집기는 처음부터 소스 어댑터 인터페이스로 작성한다:

```js
// collectors/base.js — 모든 수집기가 구현할 계약
// fetchPrices(product) → Promise<{ prices: number[], source: string }>
// prices: 이상치 제거 전 원시 가격 배열. 가공·저장은 공통 파이프라인이 담당.

// collectors/naver.js    — v2.0 기본 (7/31까지)
// collectors/danawa.js   — 후보 A: 다나와 중고/리퍼 가격 (robots.txt 및 약관 검토 후 결정)
// collectors/coupang.js  — 후보 B: 쿠팡 파트너스 API (리퍼·반품 상품가 — 제휴 수익 겸용)
// collectors/manual.js   — 후보 C: 수동/반자동 입력 폴백 (주 1회 운영자 입력용 CSV 임포트)
```

- 활성 소스는 `config/sources.json`에서 모델 카테고리별로 지정 (폰은 A소스, 대형가전은 B소스 등 혼용 가능).
- **전환 시나리오**: ① 7/31까지 네이버로 일별 적재 극대화(지금 즉시 cron 가동) → ② 8월부터 후보 소스 중 법적 검토 통과분으로 스위치 → ③ 공백기가 생기면 그래프에는 기존 누적분 + v1 감가 모델 보간치를 점선으로 표시하고 "추정치" 라벨 명시.
- 다나와/에누리 전환 시 반드시 사전 확인: robots.txt 허용 여부, 이용약관의 자동수집 금지 조항, 요청 빈도(일 1회 배치 수준 유지). **불허 판정 시 크롤링하지 않고 후보 B/C로 간다** — "법적 리스크 제로"가 이 서비스의 정체성이다.

### 3.5 GitHub Actions 워크플로 규격

```yaml
# .github/workflows/collect.yml
on:
  schedule: [{ cron: "0 21 * * *" }]   # KST 06:00 매일
  workflow_dispatch:                    # 수동 실행 허용
# jobs: checkout → node collect.js → data/ 변경분 자동 커밋 → Pages 재배포
```

- 실패 알림: Actions 실패 시 GitHub 이메일 알림 활용 (booyoung.kim 계정). 3일 연속 실패 시 그래프에 "업데이트 지연" 배너가 자동 표시되도록 `updatedAt` 경과일 체크를 프론트에 구현.

## 4. 3단계 수익화 모델 (Monetization Strategy)

### 4.1 1단계 — 광고 + 제휴 (지금 ~ 월 3만 UV)

| 항목 | 실행 내용 |
|---|---|
| 구글 애드센스 | 이미 `ads.txt` 배치 완료. v2에서 승인 확률을 높이는 요소: 시세 그래프(독자 콘텐츠성), 꿀팁 10편, 개인정보처리방침(완료). 광고 슬롯: ① 시세 카드와 그래프 사이 1개 ② 페이지 하단 1개. **First View(시세 요약 카드 위)에는 광고 배치 금지** — 이탈률·애드센스 정책 리스크. |
| 쿠팡 파트너스 | 시세 페이지 하단에 "새 제품 가격이 궁금하다면" 블록 → 동일 모델 신품/리퍼 쿠팡 링크. 수수료 ~3%. **필수 고지 문구를 링크 인접 위치에 명시**: "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." |
| 가전 렌탈 제휴 | 대형가전(냉장고·세탁기·에어컨) 페이지 한정: "중고 대신 렌탈은 어때요?" CTA → 렌탈 제휴 링크(제휴마케팅 플랫폼: 링크프라이스/쿠팡CPA 등). 건당 리드 수수료가 광고 CPC보다 높음. |

### 4.2 2단계 — 리드 제너레이션 (월 3만 UV ~)

- **상품**: "내 가전 감가상각 리포트" (무료, 이메일 발송)
  - 내용: 선택 모델의 12개월 시세 전망(감가 곡선), 최적 판매 타이밍, 상태 등급별 예상가표, 판매 글 템플릿.
  - 생성: 기존 감가 로직 + 누적 시세 데이터로 자동 생성 (HTML 이메일 1종 템플릿).
- **수집 흐름**: 시세 페이지 그래프 하단 CTA "이 제품, 언제 팔면 가장 좋을까요? → 리포트 무료 받기" → 이메일 입력 폼.
- **인프라**: 폼 제출 → Formspree/Stibee(스티비) 무료 티어 → 자동 발송. 서버 불필요.
- **컴플라이언스 (필수)**: 개인정보 수집·이용 동의 체크박스(수집 항목: 이메일 / 목적: 리포트 발송 및 시세 소식 안내 / 보유기간: 동의 철회 시까지), 수신거부 링크 포함. `privacy.html` 개정 필요.
- **KPI**: 조회→이메일 전환율 3% 목표. 이 DB가 3단계의 자산이 된다.

### 4.3 3단계 — B2B 연계 (이메일 DB 5천+ / 월 10만 UV ~)

- **즉시 매입 연계 (C2B 리드 판매)**: 시세 조회 결과 화면에 "동네 매입 업체에 바로 팔기 — 예상 매입가 확인" 버튼 → 사용자 지역+모델+상태 정보를 제휴 매입 업체(중고 가전 매입상, 리퍼 업체)에 전달 → **건당 리드 수수료 5,000~15,000원**. 아웃링크 클릭 데이터(2.1 F-04의 GA 이벤트)로 "우리 트래픽이 구매 의도 트래픽"임을 증명하는 제안서 작성.
- **시세 데이터 구독 (Pro)**: 누적된 history.csv 기반 시세 API/대시보드를 중고 매입 업체·리퍼 업체에 월 구독 판매 (월 3~5만원, 초기 목표 10개사). 이 시점에 Supabase 이관 + API 키 발급 체계 구축.
- **우선순위 판단 기준**: 리드 판매가 구독보다 먼저다 — 영업 대상이 같고(매입 업체), 리드 판매로 신뢰를 쌓은 뒤 구독을 업셀하는 순서.

### 5.2 동적 URL 및 메타 태그 자동 생성 (build.js 확장)

현재 build.js의 정적 생성 구조를 그대로 쓰되, 템플릿을 강화한다:

```
URL 규격:   /price/{slug}.html          (기존 유지 — 색인된 URL 절대 변경 금지)
Title:      {제품명} 중고가 시세 — {YYYY년 M월} 최신 | 중고시세
Description: {제품명} 중고 가격, 지금 얼마일까? 최근 3개월 평균 {avg}원,
            최고 {max}원 · 최저 {min}원. 무료 시세 그래프와 상태별 예상가 확인.
```

- **시세 숫자를 메타에 박는 것이 핵심 차별화** — 검색 결과에서 CTR을 끌어올리는 요소. 단, 빌드 시점 데이터이므로 "YYYY년 M월 기준" 표기로 신선도 명시. 월 1회 이상 전체 리빌드하여 메타 갱신.
- **구조화 데이터 (JSON-LD)**: `Product` + `AggregateOffer` 스키마 삽입:
  ```json
  { "@type": "Product", "name": "갤럭시 S24",
    "offers": { "@type": "AggregateOffer", "lowPrice": 548000,
                "highPrice": 701000, "priceCurrency": "KRW", "offerCount": 37 } }
  ```
  → 구글 검색 결과에 가격 리치스니펫 노출 가능.
- **FAQ 스키마**: 모델 페이지마다 자동 생성 Q&A 3개 ("갤럭시 S24 중고가는 얼마인가요?" / "지금 팔아도 되나요?" / "어디서 팔 수 있나요?") — 데이터에서 답변 문장 자동 조립.
- **내부 링크 구조**: 카테고리 허브(`/price/index.html`) → 모델 페이지 → 관련 모델 3개 + 관련 꿀팁 2개 상호 링크. 고아 페이지 0 유지.

### 5.3 콘텐츠 로드맵 (검색 수요 기반)

- 모델 페이지가 "{모델명} 중고가" 롱테일을 담당, 꿀팁이 "{카테고리} 파는법/버리는법" 정보성 쿼리를 담당하는 이원 구조 유지.

## 8. SEO 선점 전략 — "{모델명} 중고가" 틈새 공략

> **포지셔닝 확정 (2026-07-14)**: 본 프로젝트는 "SEO 기반 애드센스 콘텐츠 사이트 + 향후 옵션(시세 데이터)"으로 정의한다. 첫 마일스톤은 **구글 애드센스 승인**이며, 시세 그래프(3장)는 랭킹 장치가 아니라 체류시간·재방문 장치로 병렬 운영한다.

### 8.1 전략 요약

검색량은 있는데 제대로 된 답 페이지가 없는 **대형가전 롱테일 키워드**를 "질문에 즉답하는 페이지"로 하나씩 점령하고, 서치콘솔 데이터가 다음 타겟을 알려주는 루프를 돌린다. 폰·노트북처럼 기존 시세 서비스(세티즌 등)가 점령한 고볼륨 키워드는 후순위.

### 8.2 키워드 선정 프로세스

- **도구**: 네이버 검색광고 키워드도구(무료) + 구글 Keyword Planner. 서치콘솔 데이터가 쌓이면 그것이 제1 소스가 된다.
- **선정 기준**: 월 검색량 500~5,000 + 검색 결과 1페이지에 시세 요약 페이지가 부재한 키워드.
- **우선 카테고리**: 세탁기·건조기·워시타워 / 냉장고·김치냉장고 / 에어컨 / 식기세척기 / 의류관리기 / 청소기 / 정수기·안마의자(신규 후보).
- **시나리오 키워드 병행** (경쟁 0, 거래 의도 강함): "이사 세탁기 팔까 버릴까", "전세입자 가전 인수 가격", "혼수 가전 중고", "원룸 가전 처분" 등 — 꿀팁 에세이가 담당.

### 8.3 페이지 고유성 규칙 (thin content 방어 = 애드센스 승인 방어)

- 모델 페이지가 숫자만 다른 붕어빵이 되면 구글이 도어웨이 페이지로 묶어 색인 제외할 수 있고 애드센스 심사도 탈락한다. **모든 신규 모델 페이지는 고유 문단 필수.**
- 구현: `products.json`에 `notes` 필드(모델별 거래 팁 2~3문장) → build.js가 "{모델명} 거래 포인트" 섹션으로 렌더링. ✅ 2026-07-14 대형·생활가전 상위 20개 모델 적용 완료.
- `notes` 작성 기준: 그 모델(군)에서만 성립하는 내용일 것 — 운송 조건, 소모품, 계절성, 모델 파생 구분, 흥정 포인트. 카테고리 공통 얘기는 `CAT_INTRO`가 이미 담당하므로 중복 금지.
- 잔여 39개 모델(폰·노트북·태블릿·TV·게임기)은 서치콘솔에서 노출이 확인되는 모델부터 순차 작성.

### 8.4 경험 콘텐츠 로드맵 (E-E-A-T)

월 2편 페이스로 경험+정보 하이브리드 에세이 발행. 후보 (우선순위순):

1. **"전세입자한테 가전 인수 제안받았을 때 — 230만원 불렀다가 결국 다 새로 산 이야기"** (창업자 실화. 세탁기콤보·냉장고·정수기 견적 계산 과정, 협상 결렬, 사후 복기) — 이 서비스의 존재 이유이자 독창성 증거.
2. "중고 정수기, 사도 될까? 렌탈 약정과 비교해 봤다"
3. "이사 나가며 가전 3개 팔아본 후기 — 플랫폼별 실제 반응"
4. "중고 김치냉장고 직거래 체크리스트"

### 8.5 채널 전략

- **주전장 = 구글** (+빙): 네이버는 자사 블로그·카페 우대로 독립 사이트의 통합검색 노출이 어렵다. 애드센스 트래픽의 주력도 구글 유입.
- **네이버 = 위성**: 서치어드바이저 웹문서 노출 유지, RSS 제출. (2단계) 네이버 블로그에 요약본 + 원문 링크 유입 구조.

### 8.6 성장 루프 운영 (주간 루틴)

1. 서치콘솔에서 **노출 발생 + 순위 11~30위** 쿼리 확인 (주 1회)
2. 해당 페이지 보강 (notes 추가/확장, 제목 조정) → 1페이지 진입이 가장 싼 성장
3. 노출이 잡히는 인접 쿼리의 모델 페이지 신규 추가 — **주 5~10개 상한** (대량 투하는 스팸 신호)
4. 월 1회 전체 리빌드 (`node build.js`) — 제목·본문의 연도 표기 및 시세 신선도 갱신
